# Issue: Unbounded TraceEvent Channel Leak

## Context
In `ProfilerTraceListener.kt`, trace events received from the daemon are forwarded asynchronously to a `collectorThread` via a Kotlin Channel to decouple trace event capture from analysis and minimize seccomp notify loop latency.

## The Bug
The listener defines `val eventChannel = Channel<TraceEvent>(Channel.UNLIMITED)`. Because the channel is unbounded, it bypasses structured concurrency backpressure. If the rate of trace events generated by the daemon exceeds the rate at which the `collectorThread` can process and serialize them (e.g. during a high-throughput compilation or intensive I/O workload), the channel will grow indefinitely. This causes a severe native and JVM memory leak (each `TraceEvent` retains a captured `StackTraceElement` array and multiple paths), eventually leading to a complete Denial of Service (DoS) and `OutOfMemoryError`.

## Recommendation
Remove `Channel.UNLIMITED` and define a reasonable bounded capacity (e.g., `Channel.BUFFERED` or an explicit capacity like `1000`). If the buffer fills, the `send` (or `trySend` currently used) mechanism should either suspend (applying backpressure to the seccomp tracee process itself, throttling it safely) or drop events with a clear warning depending on the required reliability semantics of the profiler.
